# Architecture Review
Generated: 2026-09-10T22:14:38.683Z

## Summary
The codebase has a clear component library ('Pre-built, do not reimplement') pattern and consistent domain/datetime/storage separation, which is a strong foundation. However, several pages bypass the canonical storage-key constants and default-settings values by re-declaring their own local copies (exactly the mistake the code's own comments warn against), there's a stale/orphaned `contract.ts` spec file whose types don't match the real implementation, and small utility logic (haptics firing, session date normalization) is copy-pasted instead of shared.

## Issues
### Critical
- [duplication] Storage key constants (SESSIONS_KEY, SETTINGS_KEY, REPORT_UNLOCK_KEY) are centrally defined and exported from lib/types.ts with an explicit comment warning not to re-type key strings per screen ('오타 하나가 조용히 다른 저장소를 가리킨다'), yet Calendar.tsx, History.tsx, Home.tsx, and Report.tsx each re-declare their own local string-literal constants instead of importing the shared ones. Report.tsx even renames it locally to UNLOCK_KEY, diverging from the canonical REPORT_UNLOCK_KEY name. — Files: src/lib/types.ts, src/pages/Calendar.tsx, src/pages/History.tsx, src/pages/Home.tsx, src/pages/Report.tsx / Fix: Remove all local key constant declarations and import SESSIONS_KEY/SETTINGS_KEY/REPORT_UNLOCK_KEY from lib/types.ts everywhere, as Badges.tsx, More.tsx, Settings.tsx, and Rank.tsx already correctly do.

None of these contract.ts types appear imported or used anywhere in the codebase. — Files: src/lib/contract.ts, src/lib/domain.ts, src/lib/datetime.ts / Fix: Delete contract.ts if it's stale scaffold output, or if it must remain as a design contract, reconcile its type/function names with the real implementation so it doesn't silently drift out of sync.
- [duplication] The haptic-feedback try/catch wrapper around generateHapticFeedback (guarding against throw outside the Toss WebView) is independently reimplemented in FloatingTabBar.tsx, BottomCTA.tsx (fireHaptic with a type param), History.tsx, and Settings.tsx, each with slightly different signatures. — Files: src/components/FloatingTabBar.tsx, src/components/BottomCTA.tsx, src/pages/History.tsx, src/pages/Settings.tsx / Fix: Extract a single `fireHaptic(type)` helper into src/lib/ (e.g. lib/haptics.ts) and import it everywhere instead of duplicating the try/catch.
- [duplication] sessionDateKey (normalizing FocusSession.startedAt to a dateKey) is implemented once as an internal helper in domain.ts and copy-pasted verbatim into History.tsx, with a comment acknowledging it mirrors domain.ts's internal rule instead of importing it. — Files: src/lib/domain.ts, src/pages/History.tsx / Fix: Export sessionDateKey from domain.ts and import it in History.tsx rather than maintaining two copies that can drift apart.
- [consistency] src/lib/storage.ts exports two parallel, overlapping APIs: getItem/setItem/removeItem (generic) and read/write (with fallback + session-array sorting/truncation). Every page in the codebase uses only read/write; getItem/setItem/removeItem appear unused, leaving two competing storage patterns in one module. — Files: src/lib/storage.ts / Fix: Remove the unused getItem/setItem/removeItem trio (or consolidate read/write on top of them) so there is a single storage access pattern.

### Suggestions
- [duplication] DEFAULT_GOAL_MIN_PER_DAY = 120 is hardcoded locally in Calendar.tsx, Home.tsx, and Report.tsx even though the equivalent canonical value already exists as DEFAULT_SETTINGS.goalMinPerDay in lib/types.ts (correctly used by Badges.tsx and More.tsx). — Files: src/pages/Calendar.tsx, src/pages/Home.tsx, src/pages/Report.tsx, src/lib/types.ts / Fix: Replace the local constants with DEFAULT_SETTINGS.goalMinPerDay imported from lib/types.
- [dead_code] formatCurrency and cn in src/lib/utils.ts are not referenced by any file in the codebase (only formatNumber is used, by Amount.tsx and CountUp.tsx). Similarly, TossPurchase.tsx and Sparkline.tsx are exported components not imported by any page shown. — Files: src/lib/utils.ts, src/components/TossPurchase.tsx, src/components/Sparkline.tsx / Fix: If these are intentionally pre-built for future screens, keep them but note that explicitly (e.g. in a README); otherwise remove unused exports to reduce maintenance surface.
- [naming] Function-signature type aliases use inconsistent casing between two files: contract.ts uses lowerCamelCase names (getKSTNowFn, formatDurationFn, saveSessionFn) while types.ts uses PascalCase for the same kind of alias (ToDateKeyFn, ToWeekKeyFn, IsValidDateKeyFn). — Files: src/lib/contract.ts, src/lib/types.ts / Fix: Pick one casing convention for 'Fn' type aliases (PascalCase is more idiomatic for type names) and apply it consistently, ideally after resolving/removing contract.ts.
- [structure] Domain/shared type definitions are spread across three files with overlapping responsibility (domain.ts, types.ts, contract.ts), which undercuts types.ts's own stated 'single definition principle' since contract.ts independently redefines overlapping concepts (FocusRecord vs FocusSession, WeeklyStats vs WeeklyReport, Badge vs BadgeInfo). — Files: src/lib/domain.ts, src/lib/types.ts, src/lib/contract.ts / Fix: Consolidate to two clear layers: domain.ts (implementation types + logic) and types.ts (re-exports + app-wide constants), removing or merging contract.ts.
