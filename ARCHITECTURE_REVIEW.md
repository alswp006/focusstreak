# Architecture Review
Generated: 2026-10-08T18:41:30.979Z
Score: 58/100

## Summary
The codebase is a small, well-commented React/TDS mini-app with a sensible layering (components → lib → pages) and a defensive approach to SDK access. It has no circular dependencies that are visible. However, the shared contracts in `lib/types.ts` are largely ignored by the pages: storage keys, constants, helpers and the haptic wrapper are copy-pasted across many files. Error-handling and import conventions are inconsistent, and there are several dead or unused modules.

- [structure] The three type files overlap and disagree. `lib/contract.ts` ('auto-generated, do not edit') declares `FocusRecord`, `SessionData`, `Badge`, `Tag`, `WeeklyStats`, `RouteConfig` and a set of async `*Fn` types that nothing implements. - [consistency] The storage layer has two APIs with different failure semantics. `getItem` returns null on failure, but `setItem`/`removeItem` can throw. `read` and `write` swallow everything, and `write` silently sorts and truncates anything that looks like a session array. `review.ts` uses `getItem`/`setItem` and a try/catch around the setter, while pages use `read`/`write`. Also, `getItem` treats falsy raw values as null, and `write` applies domain-specific truncation inside a generic storage function. — Files: src/lib/storage.ts, src/lib/review.ts, src/pages/History.tsx, src/pages/Report.tsx / Fix: Collapse to one non-throwing pair (`read`/`write`, plus `remove`) and migrate `review.ts` to it. Move session sorting and truncation into a `saveSessions()` in a domain/repository module.
- [consistency] Components and pages read from localStorage synchronously during render (`read(...)` in the body of Badges, More, Calendar, Rank, Settings), while Home, History and Report load via `useState` initializers or effects. Data can go stale and the work is repeated on every render. There is no shared state layer, so a session written in Home is not visible to other mounted components until they re-read. Pages also differ on how they show loading and empty states (Home has a loading skeleton, others have none). — Files: src/pages/Badges.tsx, src/pages/More.tsx, src/pages/Calendar.tsx, src/pages/Home.tsx, src/pages/History.tsx, src/pages/Report.tsx / Fix: Introduce a small store or hook (e.g. `useSessions()`/`useSettings()` built on `useSyncExternalStore` over localStorage) and use it consistently. Standardize on `LoadingState` and `EmptyState`.
